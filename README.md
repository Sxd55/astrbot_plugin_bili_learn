# Savage Evolution（astrbot_plugin_bili_learn）

从 B 站**公开视频**学习短摘要，写入 AstrBot 官方知识库；也支持用户发链接/BV号时 AI **按需读取单个视频**。Cookie 选填。不点赞、不评论、不私信、不投币、不改人格文件。

当前版本 `v1.9.1`。需要 AstrBot `>= 4.5.7`（官方知识库 + LLM 工具；兴趣词表格需要 `>= 4.10.4`）。

和 Savage Type 的分工：本插件管「世界知识」；Savage 管「谁说过什么」。本插件**不写** Savage 事实库。主链检索走 AstrBot 知识库 RAG。

## 它做什么

1. 按兴趣关键词顺序搜索公开视频（第一个词刷够每轮目标再刷下一个）。
2. 拉标题、UP、分区、简介、时长；读多 P 字幕（默认前 3 P，可配 0=全部），优先中文轨；超长字幕取开头/中间/结尾三段（默认上限 12000 字）。
3. 用聊天模型写成 3–7 条要点的短文档（标明这是视频摘要，不是亲历），并让模型概括一个短标题、从兴趣关键词里选一个分区。
4. 写入插件自建的知识库（启动时按名称查找，没有则 `create_kb`）。文档名格式为 `分区｜概括标题.md`（例如 `AI｜多Agent终端管理工具.md`），同类型自动排在一起；同名文档已存在时不重复写入。
5. 同一 bvid 只成功入库一次（SQLite 状态机 + 知识库同名查重双保险），失败可重试。
6. **按需读**：开启 `on_demand_enabled` 后注册 `bilibili_read` 工具。用户发 B 站链接/BV号时，AI 自动调用工具，拿到摘要素材后用人设自然回复；同一视频默认也写入知识库（`on_demand_ingest`）。
7. 本地 SQLite 只做审计、去重和重试状态，不是第二套向量库。
8. **关键词门禁**：模型明确判为「其他」的视频不入库（标 `off_topic`，不重试）；按需读遇到这类视频只回复摘要、不写库。
9. **兴趣词顺序刷取**：在「兴趣词与每轮入库数量」里每个兴趣词配一个每轮入库目标。刷取按列表顺序执行——第一个词入库到目标数量，再刷下一个词。每天到点后循环轮次，直到每个关键词的当日配额刷完（无限模式则直到没有新增候选）才停。
10. **知识汇总**：某关键词未并入的视频达到阈值后，自动生成 `【汇总】分区｜主题知识.md`。汇总文档**只增不删**：旧内容一字不改，新知识以「第 N 轮新增」机械追加；生成后 AI 再复审一次，有问题则不写入并冷却 24 小时。汇总成功后按配置删除原视频文档（SQLite 仍留摘要和素材）。
11. **可信度审核**：定期（默认 7 天）用模型对照入库时留存的字幕素材，检查文档有没有虚构事实，只标记 `ok/suspect` 不修改；每天限审 N 篇摊平成本。`/bilearn audit` 查看可疑列表。审核只覆盖留有素材的文档（v1.5 起入库的），旧文档没有对照物、不参与。

## 字幕与风控（v1.2 重点）

- 启动时自动获取浏览器指纹 `buvid3/buvid4`（官方 SPI 接口，失败则生成标准 UUID+infoc 回退），与 `SESSDATA` 一起放进同一 CookieJar，避免「有 Cookie 缺指纹」被 B 站 412 拦截。
- 字幕接口用 WBI 签名的 `player/wbi/v2`（带 `fnval`），412 或缺 URL 时自动回退 `player/v2`，兼容 `subtitle_url_v2`。
- 多轨按中文优先排序，单轨下载失败自动换轨；可选的标题-字幕重叠校验（`subtitle_verify`）能拦下 B 站偶尔返回的**指向其他视频的缓存字幕**。
- 请求间隔带随机抖动；命中 `-799/-509` 或 HTTP 412 会触发全局冷却并**立即中止**（不重试），本轮任务不会硬打。
- 失败分级重试：网络/模型/知识库失败退避 1h/6h/24h 最多 3 次；无字幕的视频 7 天后最多重试 2 次；被排除和已入库的永不重试。知识库不可用时不消耗重试次数。
- 手动试跑改为后台排队：同一时间只跑一轮，连点只会排队不会并发，运行进度看运行记录。

## 运行监控

`monitor` 页面提供运行总览、cron/manual 运行记录、每次运行的阶段时间线、视频处理状态（含尝试次数）、bvid、跳过/失败原因、官方知识库 `doc_id` 和健康检查（含冷却剩余秒数）。只有拿到 `doc_id` 才算真正写入知识库；摘要生成成功但没有 `doc_id` 仍算失败。手动试跑和定时运行使用同一条 Pipeline，并在 SQLite 审计中记录 `run_id`。健康检查只读，不抓视频、不写库。

## 安装与配置

目录名保持 `astrbot_plugin_bili_learn`。拷到 `AstrBot/data/plugins/` 后重载。

配置顺序：

1. 在 AstrBot 配好 Embedding Provider（知识库创建时必填）。Rerank 可选，有预算建议配。
2. 插件设置里填写 Embedding（以及可选 Rerank）、兴趣关键词。
3. Cookie 可空。要读登录可见的 AI 字幕再填 SESSDATA，当最高权限保管，不要发到群或日志。
4. 知识库名称默认 `Bili Learn`。选定 Embedding 后不要改该库的向量维度。
5. 聊天配置里把这个知识库绑到要用的会话，否则主链不会自动检索。

常用配置：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `interest_quotas` | 空 | 兴趣词 + 每轮入库数量（表格，顺序即刷取顺序）；留空回退到 `keywords` |
| `keywords` | 聊天技巧,暧昧拉扯技巧,AI,SKILLS,提示词,科技,数码,构图,审美,艺术 | 回退用关键词；同时作为知识库分区名 |
| `unlimited_mode` | false | 无限模式：不设每日上限，一轮接一轮；**开启后立即开始刷取**，token 消耗大 |
| `run_max_videos` | 100 | 单次运行最多处理条数（含无限模式多轮），防失控 |
| `summary_provider_id` | 空 | 摘要与汇总生成用的模型；留空跟随当前会话 |
| `utility_provider_id` | 空 | 复审/审核用的便宜模型；留空跟随摘要模型 |
| `audit_excerpt_chars` | 4000 | 审核时素材上限，越小越省 |
| `daily_per_keyword` | 3 | 配额模式下每关键词每天最多入库数；0=不限 |
| `daily_quota_overrides` | 空 | 单关键词配额覆盖，如 `AI:5,科技:2` |
| `category_min_score` | 80 | 模型给分区的相关度低于该值时归入「其他」不入库；0=关闭 |
| `consolidate_enabled` | true | 达阈值自动汇总（生成+复审两次调用） |
| `consolidate_threshold` | 10 | 某关键词未并入文档达到该数量触发汇总 |
| `consolidate_delete_sources` | true | 汇总成功后删除原视频文档（SQLite 留档） |
| `audit_enabled` | true | 定期可信度审核 |
| `audit_interval_days` | 7 | 超过该天数未审的文档进入审核队列 |
| `audit_daily_limit` | 20 | 每天最多审核篇数，摊平成本 |
| `on_demand_enabled` | true | 注册 `bilibili_read` 工具，按需读视频 |
| `on_demand_ingest` | true | 按需读的视频也写入知识库（复用去重） |
| `subtitle_page_limit` | 3 | 多 P 读取数量，0=全部 |
| `subtitle_max_chars` | 12000 | 送入模型的字幕上限，超长取头/中/尾 |
| `subtitle_verify` | true | 标题-字幕匹配校验，拦截错轨字幕 |
| `max_duration_minutes` | 120 | 后台学习时长上限，按需读不受限 |
| `missing_subtitle` | desc_only | 无字幕时用简介兜底（skip=跳过并限次重试） |
| `daily_start_hour` | 1 | 每天几点开始自动刷取（0-23）；从该时间起把每个关键词的当日配额刷完；-1=只手动 |

配额与顺序说明：

- 刷取顺序 = 兴趣词列表顺序：前一个词刷到每轮目标（或每日剩余额度）后再刷下一个。
- 配额按**最终归类**计数；处理完归类后还有一道强制拦截，超出额度的视频转「延期」（缓存摘要，第二天直接入库，不重复调模型）。
- 归类相关度：模型会给出「分区」与内容的相关度分数，低于 `category_min_score` 视为「其他」，不入库。
- 按需读（工具/`/bilearn read`）不占配额；`/bilearn once` 批量运行占配额。
- 配额模式：每天到点后循环轮次，每轮每个关键词的目标 = min(每轮数量, 当日剩余)，直到所有关键词配额刷完或没有新候选。
- 无限模式没有每日上限：开启（监控页开关或配置+重载）后**立即开始刷取**，一轮结束后立即开始下一轮，直到某轮 0 新增（或达到安全上限）才停；中途关闭开关，正在跑的任务会在下一轮按配额模式收敛停止。
- `/bilearn quota` 查看今日各关键词用量，`/bilearn quota reset` 重置当天计数（方便测试）。
- 监控页支持直接编辑兴趣词和每轮数量（「保存兴趣词」按钮写回插件配置），并内置 5 套新拟物配色 + 自定义配色；运行记录和视频记录都带北京时间戳。

文档命名规则：`分区｜概括标题.md`。分区由模型从 `keywords` 里选择，选不出就按标题/简介/来源关键词兜底，再不行归入「其他」。想调整分区体系，直接改 `keywords`；已入库的旧文档不会自动改名。

## 省 token 设计

- 双模型路由：摘要和汇总生成用 `summary_provider_id`；汇总复审、可信度审核这类机械核对走 `utility_provider_id`（建议配便宜模型），留空则跟随摘要模型。
- 去重三层：bvid 状态机、知识库同名文档、延期视频复用缓存摘要（不重复调模型）。
- 字幕头中尾采样（`subtitle_max_chars`）；审核素材单独限长（`audit_excerpt_chars`，默认 4000）；汇总复审来源采样 8000 字。
- 每日定时按配额刷完即停；无限模式有 `run_max_videos`（默认 100 条/次）和 20 轮安全上限。

## 汇总文档怎么做到「只增不减」

- 汇总文档结构固定：文件头（含最后更新时间和轮次）+ 每轮一个 `## 第 N 轮新增（日期，来源：BV…）` 小节
- 生成新知识时，模型只被允许输出「已有汇总里没有的新要点」，代码负责把新小节**追加**到旧内容后面；旧内容从不重写、从不删除
- 复审（第二次模型调用）只审本轮新增部分；判为有问题则整轮不写入，并记录原因、24 小时内不重试
- 汇总文档本身也参与后续轮次和审核；原视频文档删除后，本地 SQLite 仍保留摘要和素材，可用于重建和审核

## 命令（管理员）

| 命令 | 说明 |
| --- | --- |
| `/bilearn status` | 知识库、入库/失败/汇总/审核统计 |
| `/bilearn once` | 立刻跑一轮 |
| `/bilearn read <BV号或链接>` | 不经 AI，直接读单个视频并返回摘要 |
| `/bilearn recent [n]` | 最近处理的 bvid |
| `/bilearn quota` | 查看今日各关键词配额用量 |
| `/bilearn quota reset` | 重置今日配额计数 |
| `/bilearn digest [关键词]` | 立即汇总（不带参数自动挑未并入最多的关键词） |
| `/bilearn audit` | 查看审核统计和可疑列表 |
| `/bilearn audit run [n]` | 立即审核 n 篇（默认按剩余额度） |

定时：`daily_start_hour`（默认 1，即每天凌晨 1 点，按北京时间）注册 cron。到点后按兴趣词顺序刷取，直到每个关键词的当日配额都刷完或没有新候选；-1 表示只手动跑。

## 明确不做

评论、弹幕、私信、投币、点赞、收藏、视频下载、ASR 语音转写、HTML/思维导图、人格进化、把全文当 Savage 事实。Cookie 只用于读字幕，仍不发评。
